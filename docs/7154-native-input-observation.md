## Reviewed replay decision

Authenticated live GraphQL cannot meet this experiment's no-application-write contract. `packages/backend/src/graphql/yoga.ts:92` and `packages/backend/src/websocket/setup.ts:314,345` call `recordUserActivity`, which inserts `userActivityDays` in `services/user-activity.ts:53`. WebSocket registration also writes Redis (`client-lifecycle.ts:50` → `distributed-state/connection-ops.ts:18`). Even resolver-pure `profile`, `privacySettings`, and `myBoards` would execute those transport writes. `board` can also trigger stale Redis membership cleanup. Query `betaLinks` enriches database rows/R2 thumbnails, and subscription `controllerEvents` writes activity/authorization state. No read-only root allowlist can remove transport writes, and the exceptions were not broadened.

Root approved exact pinned replay instead: snapshot `03ddb626f41d3627f587f3bff1686e2d0cc098630973d14a730f348dfe546ed1`, 1663568 compressed bytes and 346 files. This is the same frozen data/account, clock and priming sequence (including `screenshotOpenFirst`) as the successful local baseline. It holds backend data constant for CI-versus-local comparison, while explicitly changing account/backend relative to the failed LIVE crew run. The experiment can distinguish runner/native-binary behavior, not establish an account-specific cause. Real repository auth secrets are absent from observation-mode environment wiring. Credentials are fixed synthetic fixture placeholders exchanged locally only.

The existing replay implementation sets `upstreamUrl=null` and rejects an upstream (`screenshot-backend.ts:430–437`). HTTP GraphQL uses fixture replay (`1385–1399`), auth returns synthetic sessions (`1477,1596–1607`), static misses return 404 (`1533–1568`), and unknown routes return 404 (`1645`). Live WS forwarding exists only in record mode (`934–937,1767`); replay uses the local fixture responder (`1860`). Compatibility/default helpers transform recorded objects. Close rewrites fixtures only in record mode (`2017`). The sole external preparation request is the pinned public HTTPS archive GET, with byte/SHA/safe-path checks (`screenshot-fixture-snapshot.ts:145–174`); it writes only the local cache. No live proxy remains.

## Finite execution contract

The existing measurement workflow gains `observe-session-input`. Existing modes keep their capture behavior. The record checkout fetches full ancestry for the base/diff gate. Observation requires an exact native cache hit with key `macOS-ARM64-screenshot-sim-app-v1-9dd78a74eb71965f2e0876a147045ef8207d824eb936ee349170ddcd54a8082a`; a miss fails without a native build or cache save. The cached app is neither rewritten nor re-signed. Manifest hashes cover executable, debug library and plist; SDK/runtime, CLI version, diagnostic diff hash and wrapper pre/post hashes survive. Root verified the exact cache exists on the default branch (`refs/heads/main`, cache ID `9778272311`), so the diagnostic QA branch can restore it without mutating the failed train ref. The workflow records current returned cache ID/key/ref/size/timestamps before the experiment; exact-hit refusal remains mandatory.

One new primary simulator uses iOS 26.5. One Metro uses one worker. This reduced topology, replay computation and omission of normal capture work are load confounders. The job is capped at 30 minutes; the harness deadline is 23 minutes, with bounded command/process cleanup. Replay binds loopback 8119; a separate in-process sensor-only server binds loopback 8120. VM, swap, query-only pressure, top-five executable RSS and booted-device topology are sampled around the experimental contact with start/completion timestamps. Unsupported sensors are null.

Before each input, the harness requires a unique enabled checked-ON visibility parent, its observed thumb, a verified foreground bundle and a redacted screenshot. Point `(369,487)` is used only if that fresh thumb contains it; otherwise the observed parent's trailing relative point must also be inside the thumb. One point command has repeat=1 and retryTapIfNoChange=false. Pinned Maestro 2.6.1's pointer contact is configured as 0.1 seconds; XCTest synthesis elapsed is a separate value. Physical contact duration is not measured. Observation lasts ten seconds after command completion.

Logs trace raw wrapper value, captured disabled, before/after haptic without wrapping exceptions, parent start guard, queued/committed state and unique runtime/mount/attempt IDs. Target row unmount/remount, mismatched row commit identity, a row value other than OFF, changed parent, missing hop or unverified input stops that first attempt. Only a fully successful first attempt permits one fresh launch and second input. No third attempt exists. A post-tap screenshot/hierarchy or cleanup failure cannot erase the retained callback evidence.

The harness never presses Start, creates/joins/ends a session, prepares a secondary, resets credentials, or writes LEDs. Screenshot fake BLE is enabled. It never contacts the live backend for authentication, GraphQL or static fallback.
