Design notes

Each note: what the region is, what data it binds to (with dossier citations PH-nn / DB-nn / DOC-nn), and what is still open. SPECULATIVE items from the persona synthesis are never acceptance criteria. All PostHog figures are the 90-day window 2026-05-14 → 2026-08-12.

1

Global nav — exists today; add a "Gyms" link (new)

The persistent header survives the Epic 1 teardown as chrome; the only change here is a crawlable "Gyms" link to /gyms. "Open the app" is the Expo-web hand-off that already exists.

Binds: nothing new. Nav link target is the Epic 2 /gyms directory (DOC-08: searchGyms backend ready; after Epic 1, www has no gym-discovery UI unless Epic 2 ships one).

Open: confirm exactly which header chrome survives Epic 1 W-17 (layout strip) before styling against it.

2

Marketing hero — exists today, revised copy; install CTAs stay prominent

The hero remains the top install driver: 250 of 445 App Install Clicks came from hero placement (PH-13: hero|google-play 135 + hero|app-store 115). Keep both store CTAs above the fold with the existing violet-fill pill + amber glow treatment (HERO_CTA_SX in home-page-content.tsx). New: the H1/subtitle say what Boardsesh IS (marketing), because the climbing UI below it is gone. Copy shown is a proposal in climber voice; compatibility-not-endorsement wording is mandatory ("Works with Kilter…", never "Kilter app").

Binds: static i18n strings (marketing namespace, all 4 locales). Install buttons keep firing App Install Click with placement: 'hero' (PH-13).

Open: exact H1/subtitle wording — must pass the i18n glossaries (es "plafón", fr "croix/enchaîné", de "Getoppt").

3

"Start climbing on the web" — exists today (StartClimbingButton)

Hands off to the Expo-web app (SSO when signed in). Wireframe demotes it to a tertiary text link under the install pills; installs are the measured winner, web hand-off click volume is not in the dossier.

Binds: existing start-climbing-button.tsx. Install intent context: 445 install clicks / 362 users; 991 attributed installs (PH-13, PH-14).

Open: CTA hierarchy (install-first vs web-first) — no dossier fact settles it; instrument the web hand-off click before deciding.

4

Gym search entry — NEW; the homepage's replacement gym-discovery affordance

Epic 1 deletes the old home-gym-card + search drawer (5 clicks / 4 users in 90d, dismissals beat engagements — PH-11, DOC-08). This search field is a plain GET form to /gyms — no drawer, no client JS required, SSR-friendly. Facet chips pre-filter by board type. "Use my location" is optional; text search is the primary path because only 63.1% of gyms have coordinates (DB-06).

Binds: searchGyms (free-text + PostGIS ST_DWithin, default radius 50 km, board-type facets, offset paging — DOC-08). Submits ?q=&board= (+ near when geolocation granted).

Open: gym search is completely uninstrumented today (PH-12) — this PR must add events (Gym Search Performed, Gym Teaser Click). Also: keep the map itself on /gyms, not the homepage (Leaflet exists in-repo via map-location-picker, but the homepage should stay static/SSR).

5

Directory teaser card — the sparse card IS the default design

Every field on the card exists in the schema TODAY: name (100% filled), claim badge, board type + angle, and — only when present — address (23.8%) and a distance chip from lat/lng (63.1%). Board mix to expect: moonboard 52.5% / kilter 36.3% / tension 9.4%; 96% of gyms have exactly one board, ~25 gyms have 3+ (multi-board card two). No photos, no logos, no descriptions on cards — image_url is 0 of 4,740, logo 1, description 5 (DB-09). There is no city/country column (DB-06) — the location line is the free-text address or nothing.

Binds: gyms.name, gyms.address, gyms.latitude/longitude (DB-09, DB-06); user_boards.board_type + angle (DB-04); claim state from owner_id = SYSTEM vs user (DB-01, DB-10). Card links to /gym/<slug> — merged slugs 308-redirect and never 404 (DOC-03; printed QRs exist in the field).

Open: which gyms populate the homepage teasers when no geolocation is granted — any default set must not bury sparse/unclaimed listings (university-wall constraint). Dedup gate: ~46–60 physical dupes, 8 merges ever (DOC-03, DB-07) — teasers ship behind the same dedup sequencing as /gyms.

6

No-pin fallback state — 36.9% of gyms render like this

No distance chip, no map affordance, a muted "No map pin yet" line, and the claim prompt doubles as the fix ("claim it and add the pin"). The card is otherwise identical and ranks equally — never hide or rank-down sparse listings.

Binds: latitude/longitude IS NULL (DB-06: 2,991 of 4,740 have coords).

7

Claim prompt on unclaimed cards — NEW, feeds the claim funnel

2,896 unclaimed board-equipped gyms exist (DB-10); all 26 claims ever were admin-processed with zero self-serve funnel traffic (DB-02, PH-09, PH-10). The chip deep-links to the gym page's claim CTA. Whether a visible claim prompt converts is hypothesis H4 — record it, don't promise it.

Binds: claim state (DB-01/DB-10). New event required: Gym Claim CTA Click (PH-15 — no claim/scan/CTA events exist anywhere today).

Open: target of the prompt — the gym page's existing claim CTA is signed-in-only; the signed-out claim CTA is still open as #3672 (DOC-07). Claim copy must state sync-freeze out loud (DOC-09).

8

Aspiration variant — clearly labeled, NOT buildable today

Shows the same card after gym-page enrichment ships: an hours line and a one-sentence description. Today description is filled for 5 of 4,740 gyms and hours columns do not exist at all — the planned migration 0187 never landed (DB-09, DOC-09). The homepage must ship with the sparse default; this variant activates per-gym as fields appear. Hours must resist staleness (import/sync or free-text — hypothesis H7); still no photos.

Binds (future): enrichment fields from the Epic 2 gym-page-enrichment work item. Never an acceptance criterion for the homepage PR.

9

Static board-config grid — built by Epic 1 W-13 (#4366); slot reserved, not redesigned

W-13 rebuilds the board rail as static crawlable LocaleLink cards from getPopularBoardConfigs() (already SSR-fetched), using constructClimbListWithSlugs(...) — PopularBoardConfig has no slug/angle, so the slug-based builder cannot be used. Epic 2 places that grid here, below gym discovery. Sample hrefs in the wireframe are illustrative of the /board/layout/size/sets/angle/list shape only.

Binds: getPopularBoardConfigs(); URL shape per W-13's verify step ("an <a href="/kilter/…/list">-shaped link per popular board" on / and each locale root).

Open: ordering between this grid and the feature strip is Epic 2's one degree of freedom here — the grid itself (card content, links, copy) is W-13's.

10

Feature strip — repositioned as APP marketing with screenshot placeholders

Queue / Party Mode / Logbook presented as app features that end in an install prompt — on www these features no longer exist as UI post-Epic-1. Frames are real app screenshots (repo rule: no AI-generated images; capture via the screenshot tooling). Copy reuses the existing about.features voice ("Take turns without the awkward 'who's next?'").

Binds: static i18n + screenshot assets. Install CTA fires App Install Click with a new placement: 'feature-strip' so it's distinguishable from hero (PH-13).

11

Footer — NEW: SEO internal-link surface

Per-board directory links ("Gyms with a Kilter Board" → /gyms?board=kilter) create the crawl path for "kilter board near me"-shaped queries — near-zero organic today is surface absence, not proven no-demand (PH-07; hypothesis H5). Descriptive anchor text, real <a href> via LocaleLink, trademark disclaimer verbatim from the compatibility-not-endorsement rule, locale switcher for /es /fr /de.

Binds: static links + /gyms facet params (DOC-08). Gyms sitemap entries ship behind the dedup gate (DOC-03, DB-07); update packages/web/app/sitemap.ts in the same wave.

12

Page-wide rules (SEO / i18n / instrumentation)

The homepage is a search surface: unique title/description/canonical, one H1, server-rendered copy, JSON-LD Organization + WebSite. Every string is an i18n key in the marketing namespace, landed in all four locales in the same commit. Every gym URL rendered here obeys never-404 (DOC-03). New events this design requires: Gym Search Performed, Gym Teaser Click, Gym Claim CTA Click, plus the feature-strip install placement — the gym funnel is currently unmeasurable and every gym-owner persona conditions participation on a number (PH-15, PH-13).

Open questions (carry into the PM review)

  • Default teaser population without geolocation: nearest-by-IP is unreliable (no country column, DB-06; PostHog geo has known fake-cluster traps). Candidate: recently claimed + random rotation — must not systematically bury unclaimed/sparse gyms.
  • Hero CTA order: install pills vs "Start climbing on the web" — instrument first, decide later.
  • Gym count in section copy: "thousands" used deliberately — 4,740 live gyms (DB-01) includes ~46–60 known physical dupes (DOC-03); avoid a precise number until dedup settles.
  • Claim chip target: gym page anchor vs dedicated claim route — depends on #3672 resolution (DOC-07).
  • Does the feature strip earn its screenshots from the App Store screenshot pipeline (locale-matched captures exist for en/es/fr/de) or fresh web-specific captures?
