Design notes

What each region is, the file or test it binds to, and what is still open. Notes carried forward from docs/design/web-reposition/gyms-directory.html keep their original rationale; the dark-palette notes are new. The information architecture is settled — this pass is palette, surface and the two states nobody drew.

1
One header, one frame, one breadcrumb trail. The page sits directly under the single global header bar; there is no second in-page bar and no in-page back arrow. The planned PageShell primitive (title, lead, breadcrumb, width) owns the frame and the calc(var(--global-header-height) + 24px) top padding. The directory takes width="wide"; the gym page takes width="prose". Breadcrumbs are real <a href> anchors rendered with LocaleLink — so a /de/gyms/kilter visitor stays in German — and emit BreadcrumbList JSON-LD. Never router.push on a <div>. Three levels also gives the page its first two internal links before any result renders. Binds: packages/web/app/gyms/directory-page.tsx (Container maxWidth="lg" + pt: 'calc(var(--global-header-height) + 32px)', repeated in the error branch); the same literal in packages/web/app/gym/[gym_slug]/page.tsx; @/app/components/i18n/locale-link. The directory renders no breadcrumb at all today — that markup is net-new, not a restyle. Open: PageShell drops the padding to 24px where both routes hardcode 32px — pick one before the shell lands, or every ported page shifts 8px.
2
One h1, and it is load-bearing. The heading comes from facetHeading(t, facet) and is the only 40px thing on the page. A test asserts it survives even when the data fetch fails, so no refactor may make the heading conditional on results. Lead and detail paragraphs are server-rendered with live counts, capped at the prose measure. Binds: packages/web/app/gyms/directory-copy.ts (facetHeading, facetLead, facetDetail); packages/web/app/gyms/__tests__/directory-page.test.tsx:146. Mandatory open question — indexing. All four routes are robots: { index: false, follow: true } via createNoIndexMetadata. The doc comment in directory-page.tsx ties lifting that to the duplicate-gym dedup queue and the gyms sitemap shard (#4372 / #4381), not to visual quality — indexed duplicates outlive their merges in Google's cache. Design the page as the search surface it is meant to become, but a visual overhaul is the wrong PR to flip indexing in. Removing the noindex stays a one-line change, made on its own, after the queue drains.
3
Cards get a fill. This is the single biggest dark-mode fix. GymDirectoryCard renders a bare 1px solid var(--neutral-200) outline with no background. On the pale light page that read fine; on #110A20 a 1px outline is nearly invisible and the grid stops reading as a grid. Give every card the .card treatment — --surface fill, --separator hairline, 12px radius — so the fill does the work and the border only finishes the edge. Hover raises to --surface-2. Binds: packages/web/app/gyms/gym-directory-card.tsx (the Box component="li" sx block).
4
Facet chips need a border and a real selected state. They are outlined MUI Chips today; on dark an outlined chip with default borders disappears into the ground and the whole filter row goes missing. Unselected: --surface fill, --separator border, --label text. Selected: --surface-2 fill, --primary border and label, plus a soft violet ring — the state has to survive being the only styled thing in a row of four. Counts are gyms, never boards, and the hint line says so. Binds: directory-page.tsx facet Chip block; facetChipLabel in directory-copy.ts; gyms.facets.countHint. Open: only four facets exist (all, kilter, moonboard, tension). Grasshopper, Decoy and the rest of the long tail reach /gyms?boardType=… with no page of their own and no chip — decide whether they get chips that canonicalise back to /gyms, or stay unlisted.
5
Search input sits on --surface-2. Dark inputs use the elevated dark surface (#2F234A) with a violet #A78BFA focus ring — never a forced white field. The form is a plain method="get" with no JavaScript, so it works before hydration and the result is a shareable URL; the analytics island reads the result of that navigation so resultsCount is real rather than guessed at submit time. Binds: packages/web/app/gyms/gym-directory-search-form.tsx; --input-* vars in packages/web/app/components/index.css.
6
"Use my location" is opt-in, and it hides gyms. Both proximity paths hard-filter location IS NOT NULL, so switching to near-me silently drops roughly a third of the catalog. It carries the pinless notice, the radius group (10/25/50/100 km), and a one-tap "Show all gyms" back out. Denial or no support falls back to typing a town — the hint line makes that discoverable without a permission prompt. No ?lat/?lng in the URL: a shareable link should not carry somebody's position. Binds: packages/web/app/gyms/gym-directory-near-me.tsx; gyms.nearMe.pinlessNotice, nearMe.deniedBody, nearMe.unsupportedBody.
7
Map markers hardcode #fff — and this is the one place the style-prop ban cannot apply. Leaflet's divIcon takes an HTML string, so the markup is built with inline style= attributes by construction; there is no MUI component to reach for. What the rule still demands is that no literal hex survive: the strings already interpolate var(--color-primary-fill), and the #fff rings and rgba(0,0,0,0.4) shadows must become vars the same way. On a dark tile the ring should be the map ground (--semantic-background), not white — a white ring halos. Pin: --primary core, 3px ground ring. Cluster: --primary fill with dark ink, 2px ground ring, so it reads as a Boardsesh chip rather than a foreign map control. Binds: packages/web/app/gyms/gym-directory-map.tsx:210 (cluster divIcon) and :227 (single-pin divIcon); the popup anchor string just below. Open: OSM's standard raster tiles are light. A dark-styled marker set on a light tile is worse than what ships today, so the marker change and a dark tile source have to land together — or the markers stay tuned for the light tile and only the hex literals get tokenised.
8
The map is a second column, never the page. Only about 63% of gyms have a pin, so the list is primary at every width and the coverage pill states the gap on the surface that has it — bottom-left, pointerEvents: none, because Leaflet's zoom control sits top-left and a label must never swallow a click on +. OSM attribution is not optional on a public page. At ≥960px the map is a sticky right column; below that it collapses behind a Show map toggle and renders full-width above the list. Binds: gym-directory-map.tsx (the pill Chip, OSM_ATTRIBUTION, attributionControl: true); WIDE_LAYOUT = '@media (min-width: 960px)' in gym-directory-near-me.tsx.
9
Sparse is the default, and sparse never ranks lower. The card renders only schema-real fields: name, board chips, and a location line when there is one — the free-text address, a distance, or nothing at all. No photo, no description, no hours, no "verified" treatment. The long tail — university walls, garages, club boards — will never have those, and a card that leans on them quietly demotes every gym nobody filled in. A gym with no pin and no address simply loses the location line and keeps its list position. Binds: gym-directory-card.tsx (cardLocation, distanceChipKm, boardChips from directory-card-model).
10
Claim state: a badge or a quiet prompt, never a penalty. Claimed gyms get the green "✓ Claimed" pill — on dark that is a tinted fill plus a border, since --success as text alone is easy to miss at 11px. Unclaimed gyms get one quiet line ("Is this your gym?") and are otherwise identical: never hidden, never ranked down, never greyed. The prompt fires the claim-funnel event with the server-settled viewerState, so a click that beats hydration still reports the truth. Binds: packages/web/app/gyms/gym-directory-claim-link.tsx; gyms.card.claimCta; viewerState derived in directory-page.tsx from getPosthogDistinctId().
11
Pagination is a crawl path, not 40 competing URLs. 24 per page, real ?page=N anchors with rel="prev"/rel="next", and a windowed number range. One page per interaction by construction — there is no load-more loop that can drain the catalog into one request. Page 41+ is a 404 rather than a clamp (a clamp serves a 200 whose URL and highlighted page disagree), and every variant self-canonicalises to the route's own clean base. Binds: packages/web/app/gyms/gym-directory-pagination.tsx; DIRECTORY_PAGE_SIZE = 24 and DIRECTORY_MAX_PAGE = 40 in directory-facets.ts.
12
Empty state — designed, because the branch exists and nobody drew it. Today zero results renders two bare Typography lines in a Box. Give it the card surface, a muted glyph, and two ways out: clear the search, or browse every gym. Climber voice, no dead end. It is a legitimate 200 on page 1 — "no gyms match that search" is an answer; "page 40 of 2" is not, which is why only the latter 404s. Binds: directory-page.tsx pageResult.gyms.length === 0 branch; gyms.results.emptyTitle / emptyBody. Open: the near-me empty case has its own copy (nearMe.empty) and a different fix ("widen the radius"). Decide whether it reuses this panel with swapped actions or stays the plain line it is.
13
Error state — also undesigned, and it must keep the heading. When either fetch fails the page cannot state the counts its body copy is built around, so it renders the outage instead of a confident "0 gyms". The h1 stays: a test asserts the page still says what it is. Warning-toned glyph, not red — nothing is broken for the visitor, the data is late. Give them a reload and a way back. Binds: directory-page.tsx !pageResult.ok || !facetCountsResult.ok branch; gyms.error.title / error.body; __tests__/directory-page.test.tsx:146.
14
The gym page's breadcrumb link is the back pattern. It already renders a single LocaleLink home above the hero — that is the pattern replacing the deleted in-page back arrow, and it is also what keeps the page at ≥2 crawlable internal links even for a gym with no boards and no kiosk. This mockup extends it to the full Home › Gyms › gym trail so the directory is reachable from a poster scan, which is the single most common way anyone arrives here. Binds: packages/web/app/gym/[gym_slug]/page.tsx:353 (gymPage.breadcrumbHome); the "≥2 crawlable internal links" comment at :564.
15
The gym page reads the LIGHT ramp — already fixed by the token collapse. Seven call sites pull themeTokens.neutral[400] and [700] straight into sx, and those are light-ramp values: on #110A20 the body copy lands near-black on near-black. Flagging it here so nobody re-derives it — the token collapse fixes this, not the restyle. This pass should not chase individual neutral[n] reads; once the collapse lands they resolve to the dark ramp and these lines become color="text.secondary" or a semantic var. Binds: packages/web/app/gym/[gym_slug]/page.tsx lines 391, 401, 409, 420, 489, 553, 605. Same class of bug as border: '1px solid var(--neutral-200)' in gym-directory-card.tsx and gym-directory-map.tsx.
16
Cross-cutting, no single region. (a) No hardcoded hex in the implementation — every colour a CSS var from packages/web/app/components/index.css; the Leaflet strings in note 8 are the only markup that may carry inline style, and even there the values are vars. (b) i18n: every visible string through the gyms catalog in all four locales, literal t() keys only (the per-facet switch in directory-copy.ts exists precisely because t(variable) hard-fails); Spanish uses plafón for board. (c) Trademarks: "gyms with a Kilter board", never "Kilter gyms" — compatibility, never endorsement — and MoonBoard, Kilter, Tension capitalised as shown. (d) 390px: the card grid drops to one column, the map becomes a full-width block above the list behind the Show map toggle, and the facet row wraps. CSS media queries only — no useMediaQuery, which renders the wrong layout on the server and flashes on hydrate. Binds: gyms.json across en-US/es/fr/de; catalog-completeness.test.ts; vp run check:i18n; LEGAL.md.
