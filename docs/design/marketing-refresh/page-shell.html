The page shell

Five pages currently ship five near-identical CSS modules and two different ideas about where the <h1> lives. This replaces them with four server-safe primitives — PageShell, PageSection, Prose, PageCard — and deletes the second header bar that sits under the global one.1 Scope is these five pages and nothing else.16

The prose measure9

Long-form copy stops at 68 characters. That is roughly 10–12 words a line, the width a reader can track without losing the return sweep. The violet rules on either side are the measure — text never crosses them, whatever the viewport does. On width="wide" the column still holds; only cards and grids get the extra room.

07

What this deletes13

A shared shell that leaves the old modules in the tree is not a fix, it is a sixth way to lay out a page. The PR is not done until this list is gone.

  • packages/web/app/support/support.module.css Whole file. Lines 1–59 are byte-identical to about.module.css; the rails become PageCard variant="elevated".
  • packages/web/app/about/about.module.css Whole file. .pageLayout / .header / .headerTitle / .content / .heroSection all have shell equivalents; .featureList becomes ProseList.
  • packages/web/app/help/help.module.css Whole file. Its scroll-margin-top is the one rule worth keeping — it moves onto PageSection.
  • legal-content.tsx:13 — import styles from '../about/about.module.css' A page reaching across routes into another page's CSS module. Nothing else in the app does this, and it is why /legal silently inherits /about's background.
  • privacy/page.tsx — local Section() and Paragraph() Two helpers duplicating PageSection and Prose with sx literals (mb: 4, lineHeight: 1.7) that match nothing else on the site.
  • support.headerTitle · about.headerTitle · legal.headerTitle Three i18n keys × four locales = 12 strings that only ever fed the deleted second bar. vp run check:i18n:orphans fails if they linger.
  • BackButton on /about, /support, /legal The global header is always present with working nav; a back arrow under it duplicates the browser and re-enters SiteChrome's job.
Footer stand-in for SiteFooter. The document ends here — the shell uses min-height, never a bottom margin on its last child.12

Design notes

For the implementing agent. Each note states a claim, then names the file or test it depends on. A claim with no Binds line is a preference; one with a binding is a constraint.

1
New directory, not an extension of an existing one. The primitives go in packages/web/app/components/ui/page-shell/ with their own module. Do not extend page-container.module.css — it is a playlists module wearing a generic name (.heroSquareEmoji, .climbsSection, .visibilityBadge), it declares :global(:root) { --library-page-max-width }, and its max-width: 1400px is wider than anything this shell should produce. Touching it would drag the playlist FAB offset along. Binds: packages/web/app/components/ui/page-container.module.css (the :global(:root) block and .libraryPageContainer).
2
Server-safe or the whole thing is pointless. No 'use client', no hooks, no useTranslation inside any primitive. /privacy/page.tsx is an async server component and gyms/directory-page.tsx opens with import 'server-only'; a client shell would force both across the boundary and cost their server-rendered HTML — which the SEO rules require for indexable pages. Every visible string arrives as an already-resolved prop. Binds: packages/web/app/privacy/page.tsx (async RSC); packages/web/app/gyms/directory-page.tsx:1 (server-only).
3
--semantic-surface-elevated does not exist and must be added. theme-config.ts has darkTokens.semantic.surfaceElevated = '#2F234A' (and #FFFFFF on light) but it was never exposed to the .module.css layer — only --semantic-surface and --semantic-surface-overlay made it across. Add the var in both the light and dark blocks of index.css in the same PR; without it PageCard variant="elevated" has no colour to reference and someone will hardcode the hex. Binds: packages/web/app/theme/theme-config.ts:94 & :264; packages/web/app/components/index.css:44 & :213.
4
Depth is a lighter violet, never a shadow. The three existing modules separate their header strip with box-shadow: var(--shadow-xs). A black shadow against #110A20 has nothing to darken, so it reads as blur, not elevation. The ladder does the work: #110A20 → #251B3A → #2F234A, with rgba(185,170,215,0.2) as the only border value in the shell. Binds: about.module.css .header; support.module.css .header; theme-config.ts darkTokens.semantic.
5
The in-page second bar is deleted, not relocated. Today /about, /support and /legal each render a back arrow + logo + title strip immediately under the sticky global header — two bars, one of them naming a page you are already looking at. The shell replaces it with the eyebrow slot when a page genuinely needs a kicker, and with nothing when it does not. Binds: about-content.tsx (Box component="header"); support-content.tsx (same block, with the component="p" workaround); legal-content.tsx.
6
TITLE_HEADER_PAGE_PREFIXES cannot absorb those bars. Routing /support through it hits CenteredHeader, which renders Typography variant="h6" component="h1" — a SECOND <h1> on a page that already has one, failing the "exactly one h1" assertion. That branch also returns early with no nav, while the e2e suite asserts the four nav anchors on /about itself. The header stays as it is; the in-page bars die. Binds: marketing-header.tsx:66 (prefix list), :84–:115 (CenteredHeader), :374–:376 (early return); support/__tests__/support-content.test.tsx:89–95; e2e/site-chrome.spec.ts:139–147.
7
Two of the five pages gain their first <h1>. /about renders its hero as variant="h2" under a variant="h4" header title and has no h1 at all; /legal opens at variant="h3". Both are indexable marketing surfaces, so both owe a crawler one h1 carrying what people search for. Promote the hero string, do not invent a new one, and do not reuse the deleted headerTitle keys — "About" is not a search term. Binds: about-content.tsx hero block; legal-content.tsx intro section; docs SEO rules in CLAUDE.md ("Unique title… lead with what people search for").
8
titleVariant changes the size, never the tag. Some pages want a 40px title and some (legal boilerplate, a policy) want 24px — but the element is always <h1>. Keeping those two decisions separate is what lets the support test keep counting exactly one h1 while /legal still looks like a document rather than a landing page. Binds: support/__tests__/support-content.test.tsx:89–95 (h1 count + text).
9
Two widths, one measure. width="prose" is 760px and width="wide" is 1200px, replacing today's three arbitrary values: 800px (about, support), 720px (help) and MUI's Container maxWidth="md" (privacy). Inside either width, running text stops at 68ch — the width knob controls cards and grids, not line length. Binds: about.module.css .content (800px); help.module.css .content (720px); privacy/page.tsx Container maxWidth="md".
10
Anchor offsets move onto PageSection, and a live link depends on it. /help#climb-counts is linked from docs/kilter-sync.md, and it only lands correctly because help.module.css .section carries scroll-margin-top: calc(var(--global-header-height) + 16px). When that module is deleted, the rule must already be on PageSection — any section with an id gets it, not just help's. Binds: help-content.tsx CLIMB_COUNTS_SECTION_ID; help.module.css .section; docs/kilter-sync.md.
11
A card means you can act; prose does not get one. /about and /legal currently wrap their entire body in a MuiCard, which turns a document into a very tall button-shaped thing and forces the rails-on-cards colour workaround seen in support.module.css .rail (it reaches for --neutral-50 precisely because the card paper underneath already claimed --semantic-surface). Under the shell, prose sits on the page ground and PageCard is reserved for the donation rails, CTAs and link groups. Binds: about-content.tsx / legal-content.tsx MuiCard wrappers; support.module.css .rail comment.
12
Reserve height with min-height, never a trailing margin. The e2e suite measures document.documentElement.scrollHeight − footerBottom and fails above 24px, so a margin-bottom on the shell's last section — or any leftover --bottom-bar-height-style padding — shows up as dead space under the footer. min-height: 100vh on the shell root is fine; bottom padding on the last child is not. Binds: packages/web/e2e/site-chrome.spec.ts:184–202 ("ends at the footer").
13
The i18n keys go with the bars. support.headerTitle, about.headerTitle and legal.headerTitle exist only to label the deleted strip. Remove them from all four locale catalogs in the same PR — catalog-completeness.test.ts enforces parity per namespace, and vp run check:i18n:orphans flags survivors. Leave docs.headerTitle alone: /docs is not in this migration. Binds: packages/shared/i18n/locales/<locale>/marketing.json:74, :115, :152; @boardsesh/i18n catalog-completeness.test.ts. Open: /docs has the same double-header shape (docs.headerTitle at :282) — fold it into this migration, or leave it until the partner-API docs land?
14
390px is a first-class width, not a fallback. Every grid in the shell starts at minmax(0, 1fr) and widens at a breakpoint; no element carries a min-width above 390px, and the support rails already prove the pattern (grid-template-columns collapsing at 768px, CSS-only). Use CSS media queries throughout — JS breakpoint detection is banned by the repo rules. Binds: CLAUDE.md ("Use CSS media queries… Avoid JS breakpoint detection"); support.module.css .rails.
15
No hex in the implementation. Every colour in page-shell.module.css is a var(--…) from packages/web/app/components/index.css; the hex values printed on this page are documentation of what those vars resolve to in dark mode, not values to paste. Same for spacing and radii — they come from theme-config.ts via the existing tokens. Binds: CLAUDE.md ("Always use design tokens… no hardcoded values"); packages/web/app/components/index.css as the single source.
16
Scope is these five pages. Everything else is a later decision. The shell is deliberately small — no sidebar, no tabs, no sticky in-page nav — because five reading pages is all the evidence we have. Adding a slot now for a page that has not asked for one is how page-container.module.css happened. Open: should /playlists and the library pages migrate onto this shell later? They want width="wide" and a header action slot the shell does not have, and they carry a FAB offset bound to --library-page-max-width. Decide after these five ship, not before. Open: does /gyms (already an RSC with its own Container) adopt PageShell, or keep its bespoke SEO header block? It is the strongest argument for the server-safe rule either way.
