# Bounded atlas role metadata

The full-resolution Kilter 8/25 glyph appearance produced 4,971,077 bytes of atlas metadata, exceeding the existing 4 MiB CPU decoding limit despite fitting the GPU budget. A physical run stopped at that preparation rejection after observing 51 default configurations and four variants pass. Its wider cohort did not complete and is not release acceptance.

Equivalent role codes already share stamp pixels and a canonical visual identity. Atlas v2 now stores a small reference for repeated role metadata too. The alias keeps its own state code for frame lookup and the canonical identity for shared holds and editing animations. Swift and Kotlin accept only references to an earlier full canonical role within the same hold; malformed, chained, forward, self and cross-hold references fail decoding. The producer and readers ship together in the native binary. Existing expanded v2 rows remain readable.

The [structured host census](aura-role-alias-census.json) covers 84 distinct configurations: all 51 catalogue defaults, all 18 previously oversized supported samples, eight family representatives, seven actual auxiliary-marker fixtures and the Decoy foot-glyph regression, after deduplicating identical inputs. Across 535,355 role rows, expanded metadata, pixel buffers, dimensions, payload lengths and LUT bytes match exactly. Actual Swift and Kotlin readers produce the same 224-byte descriptors as an independent reference, including mirrors, editing membership, auxiliary markers and later stamp passes.

The formerly rejected manifest falls to 2,114,008 bytes. The largest measured manifest falls from 8,484,425 to 3,484,023 bytes; all 84 fit below 4 MiB. The 128 MiB aggregate application-owned GPU admission limit and 4 MiB CPU manifest limit are unchanged. Runtime admission counts atlas, scene and comparison resources retained by caches, views and in-flight work. OS drawables and driver-internal resources are outside that accounting. The host size census checks static pixel and LUT requests, not physical aggregate GPU residency. Pixel storage, shader code, the 224-byte hold descriptor, the 144-byte uniforms, resolution and pixel-error tolerance are unchanged.

All 51 geometry files are byte-identical before and after this change when generated from the same frozen configuration. The geometry codec and content hashes do not need a revision. These comparisons do not assume that runtime-style configurations generate the same files as the standard CDN prebuild configurations.

These are host correctness and size results. They do not establish final phone latency, process memory, animation cadence or physical scanout. Historical physical measurements remain attached to their original application sources; rebuilt compact-metadata artifacts and the integrated application require separate phone checks.
