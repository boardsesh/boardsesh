# Better Auth implementation evidence and decisions

Parent: [epic #6975](https://github.com/boardsesh/boardsesh/issues/6975).
Design: [Better Auth migration](better-auth-migration.md).
Started: 2026-11-04, from `origin/main` at `796746a5db`.

Production migration remains gated. For what is merged, what is open and the order of switches, see the acceptance ledger below and [better-auth-rollout.md](better-auth-rollout.md). The decision log and measurements further down are dated history, kept as written. The user's password policy is to keep the
current device signed in, revoke other credentials, and revoke every session
after forgotten-password reset.

## Execution plan

1. Implement BA-01 as an isolated, pinned, reproducible Postgres/Drizzle prototype.
2. Inventory every current identity writer and prepare the read-only BA-02 audit.
3. Run native identity, recovery, browser and OAuth protocol tests against two authorities sharing Postgres.
4. Obtain independent security and code review, fix findings, and re-review.
5. Record gate results, implement subsequent work only when its prerequisites pass, and publish a reviewable draft PR.

This file records implementation decisions and measured evidence. An unfinished
test or an upstream feature description is not a passed acceptance criterion.

### NextAuth import ratchet

`scripts/__tests__/next-auth-import-ratchet.test.ts` stops NextAuth spreading while it waits for removal. It scans tracked source under `packages/{web,backend,shared,db,mobile}` and `scripts/`, plus every `package.json`, for `next-auth`, `next-auth/*`, `@next-auth/*` and `@auth/*` (including `@auth/drizzle-adapter`), type-only imports, mocks and dynamic imports included. A file may reference them only if it is listed in `scripts/__tests__/next-auth-import-ratchet.allowlist.txt`. The test fails when an unlisted file references NextAuth, and fails again when a listed file no longer does or no longer exists, so the list only shrinks. To shrink it, delete the paths the failure message names from the allowlist in the same PR that removes the imports. The test prints how many files still import next-auth. It runs with the other `scripts/__tests__` guards.

## Compatibility constraints retained from BA-01

The deleted prototype established capabilities, not a deployed protocol. Retain
these constraints when reviewing the live implementation:

- Handoff and refresh preserve the original owner, source lineage and known or
  unknown authentication age. A recent token issue time, watch-code creation or
  account-creation receipt never proves a fresh sign-in. A committed single-use
  exchange stays consumed after its successful response is lost; failure before
  commit rolls back consumption and credential issuance together.
- Released returning-user browser transfers can omit source identity. New
  issuance time alone cannot distinguish a revoked source from a genuine new
  login. Trusted issuer ancestry, mixed-version acceptance and stale-client
  account-generation checks remain migration gates; do not infer compatibility
  from the removed prototype's conservative rejection policy.
- Historical email-keyed recovery and verification links require original-owner
  evidence and their original expiry. A current email match is not issuance
  history. New receipts bind the user, purpose, intended address, generation and
  deadline; resend supersedes older links. Verification creates neither a login
  nor fresh authentication age. Ordinary sign-out preserves valid mailbox
  proofs; credential mutations invalidate the affected older proofs.
- Authenticated password set/change keeps the requesting device signed in while
  revoking other credentials; forgotten-password reset revokes all sessions.
  Continued credentials preserve authentication age. Provider security requires
  actual reauthentication and the approved continuation contract, not a newly
  encoded cookie or a provider email match.
- Shared-domain HttpOnly cookies require trusted matching hosts. CORS and CSRF
  tests do not prove sibling-server safety, real provider behavior, Safari/device
  behavior or deployed ingress. Local transaction/socket tests do not establish
  production writer fencing, universal revocation windows, durable email delivery
  or restored-database rollback.

## Readiness decision and remaining work

The [acceptance ledger](#acceptance-ledger) distinguishes delivered code from
remaining closure evidence. BA-01's capability proof is complete and its
prototype was removed in #7620. Partner Stage A allowlist evidence is separate
from first-party authority activation; the prototype's earlier “no partner
launch” decision is not the current partner status.

Before first-party activation, adopt and fence every identity/security writer,
resolve ownership collisions with approved fresh evidence, and establish one
revocation authority across browser, HTTP, WebSocket, native/watch and offline
consumers. Preserve historical recovery deadlines, trusted transfer ancestry,
ordinary session renewal and the requesting-device continuation policy.

Qualify real providers, SMTP and ingress, supported iOS/Android/Garmin behavior,
queued offline ticks and account isolation, mixed-version deployments, and
mutation-safe restored-database cutover/rollback. A cooperative advisory lock is
not a fence against an old writer. No account merge, deletion, reassignment or
production authority change is authorized by this implementation record.

Use [the rollout runbook](better-auth-rollout.md) for switch ordering and
[the review guide](better-auth-review-guide.md#remaining-activation-gates) for
cross-cutting activation gates. NextAuth retirement follows those gates; the
installed-client compatibility API remains supported.
